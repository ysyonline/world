## 1. Fun Hypothesis（本关要验证的乐趣）

**经营期的每个决策，都会在总攻那晚要你的命、或救你的命。**

白天铺的每一条运输线、攒的每一根檑木、派的每一个岗，入夜都变成城墙上可点名的东西。整合关卡存在的全部意义，就是验证这句话成立。

## 2. 五支柱（设计约束；动任何一条都要重过评审）

| # | 支柱 | 含义 |
|---|---|---|
| 1 | 同一场战争，两个阶段 | 经营与战斗发生在**同一张地图、同一批资源、同一拨人口**上，不是两个关卡的拼盘 |
| 2 | 空间知识复用 | 白天记住的田区/矿点/道路，入夜就是防守知识（粮道在哪、哪面墙邻田） |
| 3 | 后果可归因 | 战斗结果能逐条回溯到经营决策（伤亡→哪个岗位空了；门破→土木没攒够） |
| 4 | 65:35 | 经营:战斗时间预算（00 §5 裁定 1），单关节奏的天平 |
| 5 | 失败可读档 | 总攻前夜自动存档（已实装），败局=再来一晚，不是重来三天 |

## 3. 结构：同图双模式 + 两级缩放

- **一张图**：经营与战斗共用同一关卡地图。地图空间定案（10-06）：**前门（正门）/ 后门（便门）两座门 + 各自门侧一段可攀墙 = 4 段布防**；**城左右两侧为天险面**（深涧/峭壁，不设门、不可进攻、不可布防）。详见 02 §3.1、06 §2。
- **两级缩放**（10-06 修正：**只有总决战推近**）：
  - **经营期 + 骚扰期 = 固定 1x 全城视角**，不缩放。理由：骚扰波（收保/关门/派兵出城）本质是**全局调度决策**，1x 才是它的正确视角
  - **总攻开始 = 自动推近到战斗视角**。镜头推近本身即「决战来了」的事件信号
  - 战斗内允许自由缩放/平移（RTS 习惯）；战斗结束自动拉回 1x——镜头回位即「战争结束」的情绪信号
  - 暂停/变速继承 02 定调（三国志12 式，暂停中可下全部指令）
- **硬约束 1 · 1x 视野下限**：1x 必须完整装下「城内 + 城墙 + 城外产业区 + 近郊接战区」。装不下则骚扰期「派兵出城」决策不可见 = 决策点被砍。**此条反向定义关卡地图的尺寸上限**，不是随意值。
- **硬约束 2 · 战斗缩放是验收值不是固定值**：标准为「单兵屏幕直径 ≥12px」，由地图尺寸反推，实测量 [PLACEHOLDER：预计 1.8~2.5x]。禁止写死 2x——写死会出现「这关看着太小、那关看着太糊」。
- **模式切换**：烽燧报警 → 收保 → 备战，为过渡态；总攻开始 = 进入战斗模式
- **总攻方向 RNG**（收敛后）：猛攻前门 / 猛攻后门 / 前后齐攻（齐攻低概率 = 最坏情况）。赌错方向可靠预备队补救——这是选两门而非四门的直接收益（四门赌错 = 30 分钟经营白费，与 65:35 基调打架）。
- **战斗期经营冻结**：总攻期间派工/建造/产线全部冻结（人口上了城墙或已收保）。冻结边界 [PLACEHOLDER：运输 walker 是原地停住还是瞬移回仓，实装时定]

## 9. 第 5 步「对照测试」实装口径（2026-10-06，与代码同步的事实）

§5 的 A/B/C 三信号里，**A 已自动化、B 已出实测区间、C 的机器可判部分已自动化**，C 的主观面待用户实机。

### 9.1 B 信号的测量口径（本步最关键的方法论决策）

**65:35 是「玩家注意力时间」预算，不是游戏内时长预算。**两种口径天差地别：

| 口径 | 算法 | 实测结果 | 判定 |
|---|---|---|---|
| ✗ 游戏内时长 | 经营 40 日×30 秒 vs 一场总攻几十秒 | 恒 95:5 | 永远不可能达标，**是坏口径** |
| ✓ 注意力时间 | 玩家「在做什么的那几秒」 | 见下 | 唯一可辩护口径 |

采用后者，模型为：

- **战斗侧 = 实时战场总墙钟**（`Battle.S.activeTime + pausedTime`）——**硬数据**，不依赖任何假设。
  战斗期玩家 100% 在场（1:1 实时、不能跳），暂停时也在读战况，所以含暂停。
- **经营侧 = 决策点数 × 每决策耗时**——**软数据**，含一个玩家行为假设。
  经营期玩家多数时间挂加速/发呆，只在决策瞬间消耗注意力；把 1200 秒全算进去等于假设玩家一直盯着资源栏。
- 两侧不对称是**设计正确**，不是 bug。
- **不重复计**：战斗中的微操不再计入经营决策（已含在墙钟里）。

**输出区间而非单点**：「每决策耗时」快手 4 秒 / 慢手 11 秒都合理，所以扫 3 档耗时 × 2 档决策计数口径（严/宽，共 6 组），
看整个区间落在带内还是带外。区间跨带边时如实报「待定」，不硬凑结论。

**埋点方式**：决策计数用 monkey-patch 包装 sim 的动作函数，**sim.js 一行不改** → trace 基线零漂移。

### 9.2 实测结果（B 信号·结论待定）

`node slice/pacing.js`（5 个种子 × 真实经营 40 日 + 拟人微操总攻）：

| 指标 | 实测 |
|---|---|
| 决策点数 | 91~113 次/局（严口径均值 103，宽口径 54） |
| 决策构成 | 建房子 11 · 上岗 71 · 送训 8 · 收保 6（另有 **211 次失败点击**不计——钱不够/岗位已满，玩家不会重复点，算进去会系统性高估） |
| 战斗时长 | 121 秒/局（1 场总攻） |
| 有效微操 | 18 次 |
| 比值区间 | 63.9:36.1 ～ 90.3:9.7（偏离 −1.1pp ～ +25.3pp） |
| **判定** | **【B 结论待定】**区间跨越带边（−10～+10）→ 取决于玩家决策快慢，工具无法单方裁定 |

唯一落在带内的是「每决策 4 秒 × 宽口径」这一角（−1.1pp），其余五角全部偏高 = **经营侧偏重**。
需用户实机报「实际用时」收窄假设（改 pacing.js 顶部 `PER_DECISION`），或收窄决策密度。

### 9.3 本步撞上的整合断层（比 B 更硬，待用户裁定）

**现象**：同一套最小获胜经济策略，第 40 天只能养出 **4~7 兵**；总攻是 **36 单位四色编队**（白 14 + 青 11 + 乌 5 + 骍 6）。
- 回合制（playtest.js）：**4 兵守过**（1:3 兑子 + 器械压制）→ PASSED
- 实时战斗（本步）：**4~7 兵全败**（匈奴涌入城内）→ 5/5 种子皆败

**性质**：不是 A 信号（各自数值都守恒），是**两个子系统对「一支守军该有多少人」的隐含假设不一致**——
回合制假设「少而精」（靠兑子与器械），实时战斗假设「多」。

**为什么第 4 步没抓到**：settle-smoke 用**手工构造的 33 兵**做守恒测试，
恰好跳过了「策略真能养出几个兵」这个真实问题。**测试选的输入掩盖了系统的产出能力**——这条是本步最硬的教训。

**三个修法方向**（属设计决策不是调参，已列给用户，倾向 ②）：

| | 修法 | 优点 | 代价 |
|---|---|---|---|
| ① | 修经济：训练/产出提速，40 日养 20+ 兵 | 治本 | 动摇 v0.3 经济平衡；经营期变忙会把 B 信号进一步推向「战斗太少」，一步两个问题 |
| ② | 修战斗：按实际守军规模缩放敌编队 | 顺带接上 03 §3.4「声望联动下次总攻规模」——**总攻规模现写死在 `spawnSiege`（36 单位、无 RNG），这条联动根本没接上** | 可能出现「我很强但打得和弱时一样」的观感问题 |
| ③ | 拉长准备期：总攻日 D40 → D55 | 直白 | 关卡变长，B 信号进一步偏经营 |

### 9.4 C 信号的机器可判部分

**判定标准不是「链里有几条」，而是「实际发生的每一类损失都被归到了一条」**——只列发生了的类目 = 漏归因 = C 成立。
反之链上有类目但对应损失没发生 = 虚报，同样要抓。`settle-smoke.js` 加 10 条断言（41 → 51）：

- 熟练度/设施损毁：发生 ⇔ 归因链有对应条目（**双向**，同时抓漏报与虚报）
- 【门】条目恒在（无论损不损毁——玩家需要「门这条线没问题」的确认）
- 每条归因必须指向**可操作量**（含数字/土木/檑木/火油/工匠坊/熟练度之一），纯陈述句不算归因
- 总评句必须含**行动建议**（「下次…」），只描述现象不算归因

主观面（玩家能否指着面板说出「我错在这儿，原因是上一局做了 X」）无法自动化，
已写成 `game-design/08b-第5步实机指引.md`（含三档判定标准 + 与 pacing.js 同一套的实机操作流程 + 断层修法投票）。
