## 1. Fun Hypothesis（本关要验证的乐趣）

**经营期的每个决策，都会在总攻那晚要你的命、或救你的命。**

白天铺的每一条运输线、攒的每一根檑木、派的每一个岗，入夜都变成城墙上可点名的东西。整合关卡存在的全部意义，就是验证这句话成立。

## 2. 五支柱（设计约束；动任何一条都要重过评审）

| # | 支柱 | 含义 |
|---|---|---|
| 1 | 同一场战争，两个阶段 | 经营与战斗发生在**同一张地图、同一批资源、同一拨人口**上，不是两个关卡的拼盘 |
| 2 | 空间知识复用 | 白天记住的田区/矿点/道路，入夜就是防守知识（粮道在哪、哪面墙邻田） |
| 3 | 后果可归因 | 战斗结果能逐条回溯到经营决策（伤亡→哪个岗位空了；门破→土木没攒够） |
| 4 | 65:35 | 经营:战斗时间预算（00 §5 裁定 1），单关节奏的天平 |
| 5 | 失败可读档 | 总攻前夜自动存档（已实装），败局=再来一晚，不是重来三天 |

## 3. 结构：同图双模式 + 两级缩放

- **一张图**：经营与战斗共用同一关卡地图。地图空间定案（10-06）：**前门（正门）/ 后门（便门）两座门 + 各自门侧一段可攀墙 = 4 段布防**；**城左右两侧为天险面**（深涧/峭壁，不设门、不可进攻、不可布防）。详见 02 §3.1、06 §2。
- **两级缩放**（10-06 修正：**只有总决战推近**）：
  - **经营期 + 骚扰期 = 固定 1x 全城视角**，不缩放。理由：骚扰波（收保/关门/派兵出城）本质是**全局调度决策**，1x 才是它的正确视角
  - **总攻开始 = 自动推近到战斗视角**。镜头推近本身即「决战来了」的事件信号
  - 战斗内允许自由缩放/平移（RTS 习惯）；战斗结束自动拉回 1x——镜头回位即「战争结束」的情绪信号
  - 暂停/变速继承 02 定调（三国志12 式，暂停中可下全部指令）
- **硬约束 1 · 1x 视野下限**：1x 必须完整装下「城内 + 城墙 + 城外产业区 + 近郊接战区」。装不下则骚扰期「派兵出城」决策不可见 = 决策点被砍。**此条反向定义关卡地图的尺寸上限**，不是随意值。
- **硬约束 2 · 战斗缩放是验收值不是固定值**：标准为「单兵屏幕直径 ≥12px」，由地图尺寸反推，实测量 [PLACEHOLDER：预计 1.8~2.5x]。禁止写死 2x——写死会出现「这关看着太小、那关看着太糊」。
- **模式切换**：烽燧报警 → 收保 → 备战，为过渡态；总攻开始 = 进入战斗模式
- **总攻方向 RNG**（收敛后）：猛攻前门 / 猛攻后门 / 前后齐攻（齐攻低概率 = 最坏情况）。赌错方向可靠预备队补救——这是选两门而非四门的直接收益（四门赌错 = 30 分钟经营白费，与 65:35 基调打架）。
- **战斗期经营冻结**：总攻期间派工/建造/产线全部冻结（人口上了城墙或已收保）。冻结边界 [PLACEHOLDER：运输 walker 是原地停住还是瞬移回仓，实装时定]

### 3.1 单日循环时间轴（与 00 §4.4 一致，此处展开）

白天经营（派工/运输线/商税/皇帝任务）→ 烽燧报警（三档规模情报）→ 收保 + 城门决策 → 骚扰波（**自动结算**，04 §9 纪律维持；实时化已降档关闭）→ 备战（布防/器械预置）→ **总攻 RTS** → 战后结算回写 → 下一天

## 4. 跨层接口（整合的全部新逻辑集中在这里）

### 4.1 经营 → 战斗（战前快照）

| 经营侧状态 | 进入战斗的形态 |
|---|---|
| 在编部队（兵种/人数/熟练度/装备） | 战斗单位（熟练度 80% 搏杀线继承，02） |
| 墙/门耐久 | 城防数值 |
| 器械库存（檑木/火油/重弩）+ 工匠坊产能 | 战中可用器械与补充速率 |
| 土、木存量 | 战中修门/抢修的材料与工时 |
| 布防预设 | 战斗开局站位（备战阶段可调整） |

### 4.2 战斗 → 经营（战后结算）

| 战斗侧结果 | 回写经营的形态 |
|---|---|
| 伤亡 | **永久人口损失**——01 §1 四约束立即重算（岗位空缺 → 产线降档） |
| 存活单位表现 | 熟练度变化（02） |
| 击退/溃敌规模 | 声望变动（03 §3.4；双刃剑联动下次总攻规模） |
| 门/墙受损 | 修门账单（土+木+工匠工时，次日经营期支付） |
| 设施损毁（入城铁骑/伏兵波及） | 建筑修复或重建成本 |
| 战利品 | [PLACEHOLDER：缴获折算口径，与俘虏机制（挂 EA）联动待定] |

## 5. 验收：失败信号 A/B/C

| 信号 | 定义 | 检测方式 |
|---|---|---|
| **A · 整合失败** | 接口数值漂移：战前快照与战后回写对不上（人口/物资/声望不守恒） | 无头局对账：快照→战斗→回写全程自动断言 |
| **B · 节奏失衡** | 实测经营:战斗时间比偏离 65:35 超过 [PLACEHOLDER：±10pp] | 计时埋点（结算面板已有暂停占比埋点先例） |
| **C · 认知断裂** | 玩家输了却不知道是经营期哪个决策导致的 | 用户实机试玩 + 结算页「归因链」呈现（损失逐条挂到决策） |

**C 是生死线**：支柱 3「后果可归因」若立不住，①同图双模式即不成立，回退重议分场景方案。
